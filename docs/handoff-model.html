缺口 A · resume 打断累积链

迭代更新的来源只有一跳：previousRun.previousHandoffId。而 resume run 永远没有这个字段，于是 <previous-summary> 不出现，之前所有轮次都不再被更新进新 checkpoint。

orchestrator.ts：consumedHandoff = previousRun.previousHandoffId ? … : undefined　·　 v1.test.ts：resume must not create a handoff

缺口 B · 中间轮的用户提问根本没进摘要

序列化时只在「没有任何 user 事件」时补一句原始任务。而 pi / opencode / claude-code / codex 都只发 assistant 事件，只有 mock 适配器会写 user 事件 —— 所以 提问2..提问n 对 summarizer 完全不可见。

handoffSummary.ts：serializeRunConversation 的 taskLabel(task) 兜底　·　 pi.ts / opencode.ts / claudecode.ts / codex.ts 均为 role: "assistant"

锚点规则：从最新的、带 compactionSummary 的 handoff 之后开始覆盖 —— resume 轮次不会再打断累积， 已被 checkpoint 覆盖的 run 也不会重复摘要。

原则：降级永不静默。摘要模型不可用时不再自动退回启发式 —— 要么给出真正的模型摘要， 要么报错并要求用户显式选择使用结构化降级上下文。

继续任务时自动需要 handoff
⚠ 返回 409 handoff-unavailable + 原因；前端弹窗说明「将收到结构化摘要而非模型摘要」， 用户确认后才带 allowDegradedHandoff: true 重试

为什么不是「一律报错」

长任务恰恰最需要 handoff；纯 harness-native（Codex / Claude Code 跑自己账号、未配 provider）也需要跨 Harness 切换； 切换瞬间的 429/5xx 不该把机械操作变成死路。因此：根因用分块摘要消除（长任务不再超限）， 残余失败用显式选择兜住，而不是把它变成不可完成。

代码落点
HandoffUnavailableError · code handoff-unavailable ContinueTaskInput.allowDegradedHandoff Handoff.generation（method / detail / chunks） server 409 + allowDegraded: true Chunked summarization（输入预算） 总预算 HANDOFF_GENERATION_BUDGET_MS（默认 180s） AbortSignal 透传到 model call / 重试退避

时间边界：单次调用 ≤ 120s（安全上限）→ 整次生成 ≤ 180s（总预算，含分块与重试）。 客户端断开或点 Cancel 会通过 AbortSignal 真正中止服务端工作；被取消的请求始终按取消处理，不会落成降级 handoff。

这是两个不同的东西。AgentFabric 只负责 Handoff；会话内的上下文压缩属于 harness。
对照

Context Compaction（上下文压缩）

作用域：会话内 native session：继续用同一个 触发：harness 自动（token 超限） 产物：注入回同一会话的 checkpoint 实现者：harness 自己（pi / Claude Code）

Handoff（交接）

作用域：跨会话（通常跨 harness） native session：旧的结束，新的开始 触发：用户显式动作 产物：落库的 Handoff，新会话唯一上下文 实现者：AgentFabric

AgentFabric 从不压缩活会话：那是 harness 在它自己的 native session 里做的事。 core/handoffSummary.ts 只是借用 pi compaction 的提示词与格式来写 handoff。

Handoff 不是摘要。现在的目标是：在目标 context budget 允许的范围内，最大限度重建上一个 harness 的工作前沿。 摘要只是「装不下的历史」的降级表示 —— Summarize what does not fit. Do not summarize away what does fit.

Checkpoint 预算
