# Task: Harden the Existing AgentFabric Handoff Implementation

你正在继续优化 AgentFabric 当前已经完成的 Handoff Context Bundle 实现。

当前 Handoff 的核心架构已经成立：

```text
historical context
    ↓
selection
    ↓
checkpoint + pinned context + retained trajectory
    ↓
target harness
```

本次任务不是重新设计 Handoff。

不要推翻已有 Context Bundle 架构。

本次目标是解决当前实现中的 correctness、budget accuracy、target capability 和 instruction semantics 问题，使现有实现达到更可靠的 production-ready 状态。

---

# 1. Overall Goal

现有 Handoff 已经满足：

```text
Handoff != summary-only
```

本次优化后必须进一步满足：

```text
1. retained context 不存在隐性信息黑洞
2. tool call/result pairing 在缺失原生 call ID 时仍可靠
3. handoff budget 真正根据 target harness capability 生效
4. reported handoff budget 与实际 rendered handoff 基本一致
5. multilingual context 不会被明显低估 token usage
6. historical user instructions 有明确的时间优先级语义
7. old-prefix summarization 不因 head truncation 丢失最关键的尾部信息
```

---

# 2. Scope

本次必须处理：

1. tool call/result pairing without native call ID
2. partial-retention coverage semantics
3. target harness context-window resolution
4. complete handoff budget accounting
5. multilingual token estimation
6. historical user instruction supersession semantics
7. oversized old-prefix summarization behavior
8. tests
9. documentation if externally observable behavior changes

本次不要：

* 重新设计整个 Handoff Context Bundle
* 把 Handoff 改回 summary-first
* 引入新的 LLM selector
* 大规模重构 unrelated runtime architecture
* 为历史旧 Handoff schema 增加 compatibility layer
* 做 migration
* 修改无关业务逻辑
* commit
* push

# 3. Requirement A — Reliable Tool Call / Result Pairing Without Native Call IDs

当前 Handoff 必须保证：

```text
tool call
+
corresponding tool result
```

在没有 native `toolCallId` / `callId` 的 runtime 中仍然可以作为一个 logical interaction 保留下来。

不能出现：

```text
tool call
synthetic tool call
tool result
```

被错误拆成三个 unrelated context units。

也不能仅仅因为两个 tool 名称相同，就错误地把 result 配给错误的 call。

---

## Required Behavior

当 runtime 提供稳定 native call ID 时：

```text
使用 native ID 进行 pairing
```

当 runtime 没有 call ID 时：

仍然必须保证：

```text
call/result pairing deterministic
```

尤其必须正确处理：

```text
read A
read B
result A
result B
```

以及：

```text
shell command
shell output
```

等情况。

不得简单使用：

```text
toolName
```

作为所有同名调用共享的唯一 identity。

---

# 4. Requirement B — Partial Retention Must Not Mean Fully Covered

这是本次最重要的 correctness requirement 之一。

如果一个 context item 原始内容是：

```text
80K tokens
```

但 retained context 由于 budget 原因只保存：

```text
head + omission marker + tail
```

那么这个 item 只是：

```text
partially retained
```

不能被视为：

```text
fully represented
```

---

## Required Invariant

必须区分以下语义：

```text
fully retained
partially retained
intentionally omitted because reconstructable
not retained
```

只有真正已经完整表达、或者明确属于可重建内容的 context，才能安全地从 checkpoint summary source 中完全排除。

---

## Forbidden Behavior

下面的行为不允许：

```text
original content = 80K

retained content = 10K head/tail

selector marks original item fully covered

checkpoint excludes original item

middle 70K disappears forever
```

这会产生 information black hole。

---

## Required Behavior

对于 partial retention：

```text
retained raw portion
+
checkpoint representation of omitted semantics
```

必须至少存在一种可靠覆盖。

不要求 checkpoint 重复整个 raw content。

但不能让 omitted middle：

```text
既不 retained
也不 summarized
```

---

# 5. Requirement C — Target Harness Context Window Must Reflect the Actual Target

Handoff budget 的核心原则仍然是：

```text
effectiveHandoffBudget =
min(
  configuredMaxHandoffTokens,
  targetContextWindow * configuredRatio
)
```

默认目标保持：

```text
maxHandoffTokens = 150K
ratio = 15%
```

因此：

```text
1M context → 150K
512K context → 76.8K
256K context → 38.4K
128K context → 19.2K
```

---

## Current Problem to Eliminate

对于 native harness target，例如：

```text
Codex
Claude Code
Pi
OpenCode
```

不能仅仅因为 AgentFabric 当前没有 target model metadata，就永远退化到：

```text
unknown
→ 128K default
→ 19.2K handoff
```

如果 target harness 实际运行的是 1M-class model，这会直接违背 Handoff 的核心目标。

---

## Required Behavior

目标 harness 的 context capability 必须能够通过显式配置或 capability metadata 被 AgentFabric 获取。

优先级语义必须明确：

```text
explicit target/runtime capability
>
configured fallback
>
safe default
```

---

## Forbidden Behavior

不要：

```text
根据 model name 字符串猜 context window
```

不要联网查询 model context window。

不要依赖 hidden magic table，除非项目已经有统一且明确的 model capability registry。

---

# 6. Requirement D — Handoff Budget Must Account for Everything Actually Rendered

如果系统报告：

```text
estimated handoff size <= 150K
```

则实际发送给 target harness 的 Handoff body 不能因为遗漏某些 section 而明显超过该值。

必须纳入 budget accounting 的至少包括：

```text
checkpoint
pinned context
retained context
handoff metadata
workspace handoff framing
user-provided handoff notes
```

---

## User Notes

如果用户提供：

```text
userNotes
```

不能把它放在 budget calculation 之外。

例如：

```text
selected bundle = 145K
userNotes = 100K
```

系统不能仍然报告：

```text
handoff = 145K
```

然后实际生成：

```text
245K
```

---

## Current Turn / New Instruction

Receiving harness 的当前新 instruction 可以拥有独立 budget policy。

不强制一定计入 handoff bundle budget。

但必须明确：

```text
handoff payload budget
```

与：

```text
new current instruction / execution runway
```

之间的边界。

系统不能误报自己的 accounting semantics。

---

# 7. Requirement E — Multilingual Token Estimation Must Be Conservative Enough

当前 Handoff 可能同时包含：

```text
English
Chinese
Japanese
code
logs
JSON
shell output
```

不能假设所有文本都稳定满足：

```text
2 characters ≈ 1 token
```

尤其 CJK 文本不能被明显低估。

---

## Required Behavior

即使项目继续使用 heuristic estimator，而不是完整 tokenizer：

也必须满足：

```text
CJK-heavy context 不会系统性严重低估
```

允许 estimator 略微保守。

优先：

```text
actual handoff < target budget
```

而不是为了最大化利用率，频繁越过目标 context budget。

---

# 8. Requirement F — Historical User Instructions Need Explicit Supersession Semantics

Handoff 会保留历史 user messages。

历史 user message 具有 instruction authority。

但是 user instruction 会随着时间变化。

例如：

```text
User A:
Do not change the public API.

later...

User B:
You may change the public API if needed.
```

Receiving harness 不能认为两条都同时成立。

---

## Required Semantics

必须明确告诉 receiving harness：

```text
historical user messages are chronological
later user instructions supersede conflicting earlier instructions
the current user instruction is the newest instruction
```

如果不存在冲突：

历史 constraints 继续有效。

---

## Required Priority

语义上：

```text
current user instruction
>
later preserved user instruction
>
earlier preserved user instruction
```

只在发生冲突时使用 supersession。

不要错误地让后面的 unrelated user message 自动取消所有旧 constraints。

---

# 9. Requirement G — Oversized Historical Summary Input Must Not Be Head-Only

Recent retained trajectory 已经强调 execution frontier。

Old-prefix checkpoint generation 也不能在遇到巨大单个 historical turn 时简单：

```text
keep only beginning
drop all ending
```

---

## Example

Historical turn：

```text
beginning:
reading files
exploration
many logs

middle:
attempts

ending:
critical architecture decision
important failure
current conclusion
```

如果 summary input 必须缩减：

最终 summarizer 至少必须能够看到：

```text
meaningful beginning
+
meaningful ending
```

或得到语义等价的信息。

---

## Required Invariant

对于 oversized historical input：

```text
tail information must not systematically disappear
```

尤其：

```text
final error
final decision
final status
final conclusion
```

不能因为 head truncation 而永远丢失。

---

# 10. Requirement H — Do Not Regress Existing Core Handoff Semantics

下面已有行为必须继续成立。

---

## H1 — Context Bundle Remains Primary

必须继续：

```text
checkpoint
+
pinned historical context
+
recent retained trajectory
```

不能重新退化成：

```text
summary only
```

---

## H2 — Recent Raw Context Has Higher Priority Than Summary Verbosity

在有限 budget 下，应优先保护：

```text
recent user instruction
recent tool interaction
recent failure
recent assistant conclusion
historical exact constraints
```

而不是生成巨大的 checkpoint。

---

## H3 — Checkpoint Budget Remains Independent

例如：

```text
1M target
handoff budget = 150K
checkpoint output budget ≈ 8K–16K
```

绝不能因为 handoff 是 150K：

```text

```

---

## H4 — Recent Tool Results Must Not Regress to Global 2K Cap

如果 recent tool result 是：

```text
20K
```

并且 budget 足够：

必须允许保留完整 20K。

summary-only serializer 可以继续 aggressive truncation。

---

## H5 — Reconstructable Local File Reads Remain Cheap

对于共享 workspace 中仍存在的：

```text
read local file
```

尤其巨大 file body：

继续允许不完整复制到 handoff。

Receiving harness 应知道：

```text
which file/range was inspected
```

并能重新读取。

---

## H6 — Non-Reconstructable Observations Remain Higher Value

例如：

```text
test failure
compiler output
remote API response
web result
subagent result
ephemeral shell state
```

如果与当前任务相关，应获得高 retention priority。

---

## H7 — Tool Results Remain Data

Tool output 内部即使包含：

```text
IGNORE PREVIOUS INSTRUCTIONS
```

也必须明确属于：

```text
observed data
```

不能升级为 user instruction。

# 13. Expected ONE-SHOT Semantics

The resulting Handoff must satisfy all of the following.

---

## A. Target Budget

Because target native harness explicitly reports:

```text
contextWindow = 1,000,000
```

Expected:

```text
handoff max budget = 150,000 tokens
```

It must not use:

```text
19,200
```

---

## B. Checkpoint Budget

Expected:

```text
checkpoint max output <= 12,000 tokens
```

The 150K Handoff budget must not become the summary output limit.

---

## C. User Constraint Supersession

Receiving harness must understand:

Still active:

```text
Do not add new dependencies.
Keep Node 20 compatibility.
Handoff and compaction must remain separate concepts.
```

Updated constraint:

Earlier:

```text

```

Later:

```text

```

The later instruction supersedes the earlier conflicting one.

---

## D. No-ID Tool Calls

The two historical `read` calls must remain distinguishable.

The system must not semantically collapse them into:

```text

result?
result?
```

with ambiguous pairing.

---

## E. Reconstructable File Bodies

Because both files remain in the shared workspace:

```text
packages/core/src/handoff.ts
packages/core/src/handoffContext.ts
```

the Handoff does not need to copy their full historical bodies.

It should retain enough information to know:

```text
which files were inspected
```

and that they can be re-read.

---

## F. Historical Tail Must Reach Checkpoint

The checkpoint must capture this fact:

```text
native harness targets currently fall back to the default context window
when their real context capability is unavailable
```

It cannot disappear merely because it occurred near the end of a huge old turn.

---

## G. Recent Failures Must Be Raw/High Fidelity

The Handoff must preserve enough recent raw trajectory to show:

```text

```

and:

```text

```

including the reason for each failure.

---

## H. Partial Retention Must Not Cause Information Loss

If any large recent item is shortened using:

```text
head + tail
```

the omitted middle cannot automatically be treated as completely represented.

Relevant omitted semantics must remain eligible for checkpoint representation.

---

## I. User Notes Count Toward Budget

These notes:

```text
Please preserve the existing Context Bundle architecture.

```

must contribute to final handoff size accounting.

---

## J. Receiving Harness Can Continue Immediately

A reviewer given only:

```text

+

current instruction
```

must be able to answer:
