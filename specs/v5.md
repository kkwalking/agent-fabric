# AgentFabric Web 前端交互重构需求

请基于当前已经实现的 AgentFabric Web 前端继续重构。

本阶段重点不是增加新的底层功能，而是重新组织现有 Web 产品交互，使用户主要围绕：

* Task
* Agent Response
* Tool Activity
* Runtime Continuity
* Workspace
* Resume / Handoff

进行操作。

当前存在的问题是：

用户提交一个 Task 后，被直接带到 Run Detail 页面。

Run Detail 页面主要展示：

* Runtime
* Model
* Status
* Continuity
* Container Lifecycle
* Cost
* Tokens
* Native Session
* Handoff
* Events
* Logs
* Artifacts

这种页面更像：

> Run Inspector / Debug Console

而不是用户与 Agent 交互的主界面。

新的产品交互应该调整为：

> **用户操作 Task，系统执行 Run。**

> **Task 是主产品页面，Run 是执行细节。**

---

# 1. 将 Task 作为 Web 核心交互对象

用户不应该主要感知：

Run #123

而应该主要感知：

Task：介绍一下当前项目

一个 Task 可以包含多个 Run。

例如：

Task

→ User Message

→ Run #1 / Pi

→ Agent Response

→ User Message

→ Run #2 / Pi Native Resume

→ Agent Response

→ User Message

→ Handoff

→ Run #3 / OpenCode

→ Agent Response

从用户视角：

这是一个持续进行的 Agent 工作线程。

---

# 2. 新增 Task Detail / Task Thread 主页面

需要提供：

`/tasks/:taskId`

作为 AgentFabric Web 最主要的任务交互页面。

页面整体体验参考：

* Codex
* Claude Code conversation
* Chat-style Coding Agent
* Agent execution timeline

但需要保留 AgentFabric 自己的 Runtime / Workspace / Handoff 特性。

---

# 3. Task Thread 页面结构

建议页面整体结构：

顶部：

* Task Title
* Current Workspace
* Current Runtime
* Current Model
* Task Status
* Runtime Switch
* More Actions

中间：

Task Conversation / Execution Timeline

底部：

Composer / Continue Task Input

---

# 4. Task Thread 展示用户输入

每次用户提交的 Task 或 Continue Instruction，都应该作为：

User Message

展示。

例如：

User

“介绍一下当前项目”

后续：

User

“那它现在的 runtime 设计是什么？”

不要直接展示 AgentFabric 内部拼接后的完整 Harness Prompt。

---

# 5. 区分 User Prompt 和 Harness Input

当前 Run 中的 `inputInstruction` 可能包含：

* User Prompt
* Handoff Context
* Internal Context
* System Instructions
* Runtime-specific Prompt

因此不要直接把：

`inputInstruction`

作为聊天界面的 User Message。

建议在数据层明确保存：

`userPrompt`

或：

`userMessage`

表示：

> 用户实际输入的内容。

而：

`inputInstruction`

继续表示：

> AgentFabric 最终发送给 Harness 的完整执行指令。

Task Thread 只展示 `userPrompt`。

Run Inspector 可以展示完整 `inputInstruction`。

---

# 6. Agent Response 应成为主要内容

Run 执行过程中，`agent.message` 应作为主要 Assistant Message 展示。

例如：

Agent

“当前项目是一个 Agent Runtime Orchestration 平台……”

不要让用户必须从 Event JSON 中寻找 Agent 最终回答。

---

# 7. Tool Activity 使用可读形式展示

当前 Event 中的：

* tool.started
* tool.completed
* shell.command
* shell.output
* file.created
* file.modified
* artifact.created

不要直接以 JSON 原样展示在 Task 主页面。

应该转换成用户可读 Activity。

例如：

`tool.started`

→

“Read README.md”

`tool.completed`

→

“Finished reading README.md”

`shell.command`

→

“Ran `ls -la`”

`file.modified`

→

“Modified `src/index.ts`”

`artifact.created`

→

“Created REPORT.md”

---

# 8. Tool Activity 默认折叠

工具执行属于 Agent 工作过程，不应该压过最终回答。

默认展示简洁 Activity：

▸ Read README.md

▸ Ran `ls -la`

▸ Modified `src/index.ts`

▸ Ran tests

点击后再展开：

* Tool arguments
* Command
* Output
* Duration
* Result
* Error

---

# 9. Shell Output 默认不要全部展开

Shell Output 可能非常长。

Task Thread 中：

默认只展示：

* Command
* Status
* 简短摘要

例如：

Ran `npm test`

✓ 148 tests passed

如果失败：

Ran `npm test`

✗ 2 tests failed

点击后再查看完整 stdout / stderr。

---

# 10. File Activity 应优先展示语义

不要显示：

`file.modified {"path":"src/index.ts"}`

而是显示：

Modified `src/index.ts`

如果未来已有 Diff 能力，可以在这里接入。

当前阶段只需要展示文件路径和动作。

---

# 11. Run 作为一次 Assistant Turn

一个 Run 在 Task Thread 中应表现为：

User Message

→ Agent Work

→ Agent Response

而不是一个独立页面。

可以在 Run 区块底部显示轻量 Metadata：

Runtime

Model

Duration

Tokens

Cost

Status

例如：

OpenCode · deepseek-v4 · 18s · 1.2k tokens · $0.002

---

# 12. 提供 “View Run” 入口

不要删除当前 Run Detail 页面。

当前 Run Detail 页面非常适合作为：

Run Inspector

在每个 Run 对应的 Assistant Turn 中提供：

`View run`

入口。

点击进入：

`/runs/:runId`

查看：

* Raw Events
* Logs
* Artifacts
* Usage
* Runtime Session
* Native State
* Handoff
* Container Metadata
* Full Input Instruction

---

# 13. Run Detail 页面重新定位

当前 Run Detail 页面保留。

但产品定位调整为：

> 高级执行详情 / 调试 / 审计页面

而不是：

> 用户 Task 主交互页面

---

# 14. 新建 Task 后直接进入 Task Thread

当前用户点击：

New run

建议改为：

New task

用户输入：

* Task Prompt
* Runtime
* Model
* Workspace
* Agent Profile

提交后：

Create Task

→ Create Run #1

→ Navigate `/tasks/:taskId`

不要直接进入：

`/runs/:runId`

---

# 15. 左侧导航调整

当前：

* New run
* Tasks
* Dashboard

建议调整为：

* New task
* Tasks
* Dashboard

Run 不需要作为用户创建入口。

Run 可以保留在：

* Dashboard
* Task Detail
* Run History

中。

---

# 16. Task List 页面

Task List 应展示：

* Task Title
* Current Status
* Current Runtime
* Workspace
* Last Activity
* Last Agent
* Last Run Status

点击 Task：

进入：

`/tasks/:taskId`

不要只提供表格型管理体验。

---

# 17. Task Continue Composer

Task Detail 页面底部增加固定或 sticky Composer。

支持输入：

“继续修剩下的测试”

“换 OpenCode 再看看”

“不要改 public API”

提交后创建新的 Run。

---

# 18. Composer 支持 Runtime 切换

Composer 附近允许用户选择：

* Current Runtime
* Another Runtime
* Model
* Agent Profile

如果选择相同 Harness：

显示：

Resume

如果选择不同 Harness：

显示：

Handoff

例如：

Current:

Pi

选择：

Pi

→ Native Resume

选择：

OpenCode

→ Handoff

---

# 19. Resume UX

Same Harness Resume 不需要突出显示成复杂系统事件。

可以在新的 Agent Turn 顶部显示轻量状态：

Pi · resumed session

或：

OpenCode · resumed native session

不要让用户看到内部：

runtime.session.created

native.state.attached

等事件。

---

# 20. Handoff UX

不同 Harness 切换时，需要明确但简洁地展示 Handoff。

例如：

──────── Handoff ────────

Pi → OpenCode

Workspace preserved

New OpenCode session

────────────────────────

然后继续展示新的 Agent Turn。

---

# 21. Handoff 不要直接暴露完整内部 Prompt

用户可以查看 Handoff Summary。

但默认不要展示 AgentFabric 拼接的完整 Handoff Prompt。

可以提供：

View handoff

展开：

* Previous Agent
* Current Progress
* Completed Work
* Remaining Work
* Important Decisions
* Relevant Files

---

# 22. Workspace 在 Task 页面保持可见

Task Header 中持续展示：

Workspace

例如：

Workspace: `bruce-go`

Workspace 是 Task 连续性的核心之一。

用户需要能够明确知道：

当前 Agent 正在操作哪个 Workspace。

---

# 23. Runtime / Model 信息不要占据页面主体

当前 Run 页面的大卡片展示：

* status
* runtime
* model
* continuity
* lifecycle
* cost
* calls
* tokens

这些信息不要继续作为 Task 主页面首屏主体。

Task 页面只需要轻量 Metadata。

详细指标放到：

Run Inspector

或：

Usage Detail

---

# 24. Event Stream 需要转换成 Presentation Model

不要让 React 页面直接：

`events.map(JSON.stringify)`

建议增加前端 Presentation Layer。

例如：

Raw Event

→ Presentation Projector

→ Timeline Item

Timeline Item 类型可以包括：

* UserMessage
* AgentMessage
* Thinking
* ToolActivity
* CommandActivity
* FileActivity
* ArtifactActivity
* HandoffActivity
* RuntimeStatus
* ErrorActivity

不要求修改 Core Event Schema。

---

# 25. Event 合并

某些 Event 应该在 UI 中合并显示。

例如：

tool.started

*

tool.completed

应该合并成一个 Tool Activity。

`shell.command`

*

多个 `shell.output`

应该合并成一个 Command Activity。

避免 Timeline 变成大量低层事件。

---

# 26. Thinking 展示策略

如果 Harness 提供：

`agent.thinking`

可以展示成：

“Thinking…”

默认折叠。

不要让内部推理内容压过最终回答。

如果该 Harness 不适合展示详细 thinking，则只显示状态，不显示原始内容。

---

# 27. Running 状态

Run 正在执行时，Task Thread 应实时更新。

例如：

Agent

Thinking…

▸ Reading README.md

▸ Inspecting source files

▸ Running tests

随后：

Agent Message

实时使用现有 SSE Event Stream。

---

# 28. Completed 状态

Run 完成后：

在对应 Agent Turn 底部显示：

Completed

Runtime

Model

Duration

Tokens

Cost

Artifacts

View run

---

# 29. Failed 状态

Run 失败时，不应该只有：

run.failed JSON

而应该展示：

Agent run failed

原因：

xxx

并提供：

* Retry
* Continue
* Switch Runtime
* View Run

---

# 30. Cancel 行为

Running Task Turn 中提供：

Stop

停止当前 Run。

停止后：

Task 本身仍然存在。

用户可以继续发送新的 Instruction。

---

# 31. Artifacts 在 Task Thread 中可直接访问

如果 Run 产生：

* Report
* Patch
* Generated File
* Final Message
* Test Result

在对应 Agent Turn 中展示轻量 Artifact Entry。

例如：

Created:

`REPORT.md`

点击打开 Artifact Detail。

---

# 32. Task 与 Run 的产品层级

整个 Web UX 需要明确：

Task

是用户的长期工作线程。

Run

是 Task 中的一次 Agent Execution。

因此：

Task 是一级产品对象。

Run 是二级执行对象。

---

# 33. 路由建议

建议保持：

`/tasks`

Task List

`/tasks/:taskId`

Task Conversation / Execution Thread

`/runs`

Run History / Operations View

`/runs/:runId`

Run Inspector

# 34. 不要重新引入统一 Session UI

即使 Task 页面看起来像 Chat Thread：

也不要重新引入：

AgentFabric Session

这个领域概念。

Task Thread 只是：

Task + Runs + User Prompts + Agent Events

的 Presentation。

Native Session 仍然属于 Harness。

---

# 35. 不要把 Task Thread 实现成新的后端 Chat 系统

本阶段优先利用现有：

* Task
* Run
* Run.inputInstruction
* Run.userPrompt
* Events
* Handoff
* RuntimeSessionRef
* Workspace
* Artifacts

进行 UI Projection。

除必要的 `userPrompt` 字段外，不要重新设计一套 Message / Conversation / Session 后端模型。

---

# 36. 推荐视觉层级

页面主体应该优先展示：

1. User Intent
2. Agent Response
3. Agent Work Activity
4. Continue Input

其次才是：

5. Runtime
6. Model
7. Usage
8. Continuity
9. Lifecycle

不要反过来。

---

# 37. 与 Codex 类产品的差异

可以参考 Codex 的对话式 Agent 工作体验。

但 AgentFabric 应保留自己的差异化信息：

* Runtime
* Model
* Workspace
* Native Resume
* Handoff
* Run Inspector

这些信息应该作为：

Secondary Metadata

而不是页面主要内容。

---

# 38. 当前阶段不要新增功能

本次只重构 Web UX。

不要增加：

* Multi-Agent
* Workflow
* Workspace Snapshot
* Workspace Fork
* Workspace Diff
* Warm Pool
* New Runtime
* New Provider
* New Session Model

不要因为前端重构而重新设计 Core。

# 39. 最终用户体验

用户进入 AgentFabric：

点击：

New Task

输入：

“介绍一下当前项目”

选择：

Workspace

Runtime

Model

提交。

随后进入：

Task Thread

看到：

User

“介绍一下当前项目”

Agent

Thinking…

▸ Read README.md

▸ Listed project files

▸ Read source code

然后：

Agent

“当前项目是一个 Agent Runtime Orchestration 平台……”

底部输入：

“那它现在的 runtime 设计是什么？”

Native Resume。

Handoff。

同一个 Task Thread。

用户不需要理解每个 Run 的内部 Event，除非主动点击：

View Run。

---

# 40. 本阶段核心原则

请遵循：

> **Users interact with Tasks. The system executes Runs.**

> **Task is the product surface. Run is the execution detail.**

> **Agent output is primary. Infrastructure metadata is secondary.**

> **Tool events should be readable, not raw JSON.**

> **Resume and Handoff should be visible but not intrusive.**

> **Keep the existing Core model. This is primarily a presentation and interaction refactor.**

本次重构完成后的判断标准是：

> 用户提交一个 Task 后，可以像使用 Codex / Coding Agent 一样，在同一个页面看到 Agent 的工作过程和最终回答，并自然地继续输入；而现有 Run Detail 页面退回到高级执行详情和调试用途。
