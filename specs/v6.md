# AgentFabric Codex Local Harness 与跨 Harness Handoff 需求

请基于当前 AgentFabric 继续实现本地 Codex Harness 接入，目标是解决：

> 用户在 Codex 中工作到一半后，因为额度耗尽或主动切换，需要无缝切换到 Pi / OpenCode 继续任务。

本阶段重点是 **Codex Local + Handoff continuity**，不要扩展新的复杂领域模型。

## 1. 新增 Codex Local Runtime

支持本机 Codex CLI 作为 AgentFabric Harness。

要求：

* 使用本机已安装的 `codex` CLI
* 使用 Codex 自己已有的登录状态
* 支持 ChatGPT 登录后的 Codex 套餐额度
* 不要求配置 AgentFabric Provider/API Key
* 优先使用 Local Execution Backend

## 2. Harness-native Authentication

为 Runtime 支持轻量的 Credential Source 概念：

* `agentfabric`
* `harness-native`

Codex Local 默认使用：

`harness-native`

AgentFabric 不读取、不复制、不保存 Codex 的 access token、refresh token 或 auth 文件内容。

只需要检测：

* Codex CLI 是否安装
* Codex 是否已登录
* 登录状态是否可用

## 3. Codex 不强制绑定 AgentFabric Model

Codex Local Runtime 可以不依赖 AgentFabric Provider / Model。

默认使用：

* Codex 自己的账号
* Codex 自己的默认模型配置

如果未来支持 Model Override，可以作为 Codex Harness 自身配置，不要求经过 AgentFabric Provider → Model 链路。

## 4. Codex Native Session

Codex Native Thread 应直接复用现有：

`RuntimeSessionRef`

其中：

* runtimeKind = codex
* nativeSessionRef = Codex thread ID
* executionBackend = local
* resumeSupported = true

保持现有原则：

* Codex → Codex = Native Resume
* Codex → Pi = Handoff
* Codex → OpenCode = Handoff

## 5. Codex Local Execution

支持：

* 新建 Codex Thread
* 执行 Codex Task
* 捕获 Codex thread ID
* 解析主要 Codex Events
* 保存 RuntimeSessionRef
* 使用 thread ID Resume

尽量复用现有 Harness Adapter + Execution Backend 架构。

## 6. Local Codex Thread Discovery

支持发现用户本机已经存在的 Codex Threads。

优先使用 Codex 官方可用的 thread/list 等接口，而不是直接解析 `~/.codex` 内部文件格式。

支持按：

* Current Workspace / CWD
* 最近更新时间

查找相关 Codex Threads。

## 7. Read Existing Codex Thread

支持读取已有 Codex Thread 内容，不要求 Codex 再执行一次模型请求。

用于获取：

* 用户输入
* Agent 回复
* Tool Activity
* Task Progress
* Existing Thread Context

优先使用 Codex 提供的 thread/read 能力。

## 8. Import / Adopt Existing Codex Work

用户可以把 AgentFabric 外部已经存在的 Codex Thread 接入 AgentFabric。

典型流程：

Existing Codex Thread

→ Read Thread

→ Associate Workspace

→ Generate Handoff

→ Continue with Pi / OpenCode

不要求把整个 Codex Thread 转换成 AgentFabric Session。

## 9. Codex → Other Harness Handoff

当用户从 Codex 切换到 Pi / OpenCode：

Handoff 输入至少包含：

* Codex Thread History
* Current Workspace
* Existing File Changes
* Current Task
* Current Progress
* Relevant Artifacts

然后使用现有 Handoff Generator 生成高质量 Handoff。

新的 Harness 创建自己的 Native Session。

## 10. Quota Exhausted UX

当 Codex 因额度限制失败时：

不要只显示普通 Run Failed。

应识别为可切换 Harness 的场景。

Task 页面可以提示：

Codex usage limit reached.

并提供：

* Continue with Pi
* Continue with OpenCode

切换后自动生成 Handoff 并继续当前 Task。

## 11. Codex Thread Discovery UI

在 Workspace / Task 相关页面提供本地 Harness Thread 发现入口。

例如展示：

Local Codex Threads

* Thread Title
* Workspace
* Last Updated
* Turn Count

用户可以选择：

Continue in AgentFabric

## 12. 不直接解析或复制 Codex Auth

禁止：

* 将 Codex auth 导入 AgentFabric Secrets
* 读取并保存 access token
* 复制 refresh token
* 把 Codex ChatGPT 登录转换成 AgentFabric Provider

Codex 身份完全由 Codex Harness 自己管理。

## 13. 不优先 Containerize Codex

本阶段 Codex Runtime 只重点支持：

Local Execution

因为核心目标是复用用户本机已经登录的 Codex CLI 和套餐。

暂不要求 Docker Codex Runtime。

## 14. 不新增统一 Session 模型

继续保持当前设计：

* Harness sessions stay native
* Same Harness → Resume
* Different Harness → Handoff

不要引入：

* AgentFabric Unified Session
* Codex Session Schema
* Cross-Harness Session Migration

## 15. 最终验收场景

### 场景 A：AgentFabric 启动 Codex

Codex 已在本机通过 ChatGPT 登录

→ AgentFabric 选择 Codex Local

→ 不配置 Provider/API Key

→ Run 成功

→ 获取 Codex thread ID

→ 后续 Codex Native Resume 成功

### 场景 B：接管已有 Codex Thread

用户之前直接使用 Codex CLI

→ AgentFabric 发现当前 Workspace 的 Codex Thread

→ Read Existing Thread

→ 生成 Handoff

→ 切换到 Pi / OpenCode

→ 继续原任务

### 场景 C：Codex 额度耗尽

Codex 执行到一半

→ Usage Limit Reached

→ Workspace 保留

→ Codex Thread 可读取

→ 用户选择 OpenCode / Pi

→ 自动生成 Handoff

→ 新 Harness 继续执行

## 16. 核心原则

请保持：

> **Harness identity stays native.**

> **Codex subscription is used through Codex itself, not AgentFabric Provider credentials.**

> **Same Harness means Resume.**

> **Different Harness means Handoff.**

> **Workspace + Handoff preserve task continuity.**

> **AgentFabric should be able to adopt work that started outside AgentFabric.**

本阶段的核心目标不是“支持 Codex CLI”本身，而是：

> **让用户在 Codex 做到一半，即使额度耗尽，也能够通过 AgentFabric 把当前工作自然交接给另一个 Harness，而不需要重新解释上下文。**
