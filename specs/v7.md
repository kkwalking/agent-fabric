# AgentFabric Claude Code Local Harness 接入需求

请基于当前 AgentFabric 实现 **Claude Code CLI Local Harness**。

本阶段目标是：

> 允许 AgentFabric 直接调用用户本机已经登录的 Claude Code CLI，使用 Claude Code 自身的 Claude.ai 套餐与认证状态，而不是使用 AgentFabric 中配置的 LLM Provider/API Key。

同时支持：

> 用户已经在 Claude Code 中完成一部分工作后，可以由 AgentFabric 接管当前 Workspace 和 Claude Code Session，并 Handoff 给其他 Harness 继续。

## 1. 新增 Claude Code Local Runtime

新增 Claude Code 作为 AgentFabric Runtime / Harness。

要求：

- 使用本机已安装的 `claude` CLI
- 优先使用 Local Execution Backend
- 不要求 Docker
- 不要求 AgentFabric Provider
- 不要求 AgentFabric API Key
- 使用 Claude Code 自身的认证和套餐

## 2. Harness-native Authentication

Claude Code Local Runtime 使用：

`credentialSource = harness-native`

AgentFabric 不负责管理 Claude Code 的认证凭据。

禁止：

- 将 Claude Code credential 导入 AgentFabric Secret
- 复制 Claude.ai 登录 Token
- 将 Claude Code subscription 转换成 Anthropic Provider
- 读取并持久化 Claude Code 的敏感认证内容

AgentFabric 只需要检测：

- Claude Code CLI 是否安装
- CLI 是否已经登录
- Harness 当前是否可用

## 3. 不强制绑定 AgentFabric Provider / Model

Claude Code Local Runtime 默认不需要：

- AgentFabric Provider
- AgentFabric Model
- Anthropic API Key

默认使用 Claude Code 自己的：

- Account
- Subscription
- Model Configuration

因此 Harness-native Runtime 必须允许在没有 AgentFabric Model 的情况下创建 Run。

## 4. 支持 Claude Code Non-interactive Execution

AgentFabric 应通过 Claude Code CLI 的非交互模式执行 Task。

需要支持：

- 提交新 Task
- 获取结构化输出
- Streaming Output
- Agent Messages
- Tool Activity
- Errors
- Usage 信息
- Native Session ID

优先使用 Claude Code 提供的结构化 / stream JSON 输出，而不是解析 Terminal UI。

## 5. Claude Code Native Session

复用现有：

`RuntimeSessionRef`

保存 Claude Code Native Session。

例如：

- `runtimeKind = claude-code`
- `nativeSessionRef = Claude Code Session ID`
- `executionBackend = local`
- `resumeSupported = true`

不要新增 AgentFabric Claude Session Schema。

## 6. Claude Code Native Resume

保持现有原则：

**Same Harness → Native Resume**

Claude Code → Claude Code 时：

- 使用已有 Native Session ID
- 使用 Claude Code 自己的 Resume 能力
- 继续原生 Claude Code Session
- 保持原 Session 上下文

## 7. Claude Code Event Mapping

将 Claude Code 的结构化输出映射成现有 AgentFabric Events。

至少覆盖：

- Agent Message
- Thinking / Progress
- Tool Started
- Tool Completed
- Shell / Command Activity
- File Activity
- Runtime Error
- Usage

Local Claude Code 应与现有 Pi / OpenCode Runtime 一样进入 Task Thread。

## 8. Claude Code Usage

如果 Claude Code 结构化输出能够提供：

- Tokens
- Model
- Duration
- Usage

则写入现有 Run Usage。

对于 Claude.ai 套餐场景，不要求 AgentFabric 自行计算 API Cost。

不要错误地按照 Anthropic API Pricing 估算 subscription Run Cost。

## 9. Local Claude Code Session Discovery

支持发现用户在 AgentFabric 外部已经创建的 Claude Code Sessions。

目标是：

用户之前直接运行 Claude Code

→ AgentFabric 能发现这些 Session

→ 关联当前 Workspace

→ 用户可以选择接管

优先使用 Claude Code 官方支持的 Session Discovery / Resume 能力。

避免依赖不稳定的内部文件格式。

## 10. Read Existing Claude Code Session

AgentFabric 应能够获得已有 Claude Code Session 的必要上下文，用于 Handoff。

需要尽可能获得：

- User Instructions
- Agent Responses
- Task Progress
- Tool Activity
- Important Decisions
- Relevant Files
- Current Work State

如果存在官方稳定读取接口，优先使用官方接口。

如果只能依赖本地 Transcript，则需要把相关逻辑限制在 Claude Code Adapter 内，不泄漏到 AgentFabric Core。

## 11. Import / Adopt Existing Claude Code Work

支持把 AgentFabric 外部已有 Claude Code 工作接入当前 Task。

典型流程：

Existing Claude Code Session

→ Detect Workspace

→ Read Session

→ Associate / Create AgentFabric Task

→ Generate Handoff

→ Continue with another Harness

不需要把 Claude Code Session 转换成 AgentFabric Session。

## 12. Claude Code → Other Harness Handoff

当用户切换：

- Claude Code → Codex
- Claude Code → Pi
- Claude Code → OpenCode

执行现有 Handoff 流程。

Handoff 输入应包含：

- Claude Code Session Context
- Workspace
- Current File Changes
- Current Task
- Progress
- Relevant Artifacts
- Important Decisions
- Remaining Work

目标 Harness 创建自己的 Native Session。

## 13. Other Harness → Claude Code Handoff

同样支持：

- Codex → Claude Code
- Pi → Claude Code
- OpenCode → Claude Code

流程：

Previous Harness

→ Generate Handoff

→ Preserve Workspace

→ Start New Claude Code Native Session

→ Inject Handoff

→ Continue Task

## 14. Subscription / Usage Limit UX

如果 Claude Code 因套餐额度、usage limit 或类似原因无法继续：

不要只展示普通 Run Failed。

应识别为适合切换 Harness 的场景。

Task 页面可以显示：

`Claude Code usage limit reached`

并提供：

- Continue with Codex
- Continue with Pi
- Continue with OpenCode

点击后自动生成 Handoff。

## 15. Task Thread Integration

Claude Code 必须使用现有 Task Thread UX。

用户应看到：

User Message

→ Claude Code Activity

→ Agent Response

而不是 Raw CLI JSON。

Tool Activity 默认折叠。

Native Session、Harness Auth、底层 CLI 信息放到 Run Inspector。

## 16. Claude Code Runtime Status

Web UI 中可以展示轻量 Runtime 状态：

Claude Code

- CLI Installed
- Authenticated
- Credential Source: Harness Native
- Execution Backend: Local

不要展示或读取敏感 credential。

## 17. Runtime Capability

Claude Code Runtime 应正确声明能力，例如：

- Local Execution
- Harness-native Authentication
- Native Session
- Native Resume
- Streaming Events
- Handoff Import
- Handoff Export
- Workspace Support

Capability 必须反映真实 CLI 能力。

## 18. 暂不支持 Docker Claude Code

本阶段重点解决：

**本机 Claude Code CLI + 本机套餐**

暂不要求：

- Docker Claude Code
- Credential Mount
- Subscription Credential Containerization

避免增加不必要的认证复杂度。

## 19. 不新增统一 Account / Subscription 系统

不要为了 Claude Code 引入复杂的：

- Account Entity
- Subscription Entity
- Billing Identity
- Quota Manager

当前只需要复用现有轻量概念：

- `agentfabric`
- `harness-native`

即可。

## 20. 最终验收场景

### 场景 A：AgentFabric 启动 Claude Code

用户本机 Claude Code 已登录 Claude.ai

→ AgentFabric 选择 Claude Code Local

→ 不选择 AgentFabric Provider

→ 不配置 Anthropic API Key

→ Task Run 成功

→ 获取 Native Session ID

→ 后续 Native Resume 成功

### 场景 B：接管已有 Claude Code Session

用户之前直接使用 Claude Code CLI

→ AgentFabric 发现当前 Workspace 的 Claude Code Session

→ 读取已有工作上下文

→ 生成 Handoff

→ 切换 Codex / Pi / OpenCode

→ 继续工作

### 场景 C：Claude Code 额度耗尽

Claude Code 做到一半

→ Usage Limit

→ Workspace 保留

→ Session Context 可读取

→ 用户选择其他 Harness

→ Generate Handoff

→ 新 Harness 继续 Task

### 场景 D：其他 Harness 切换到 Claude Code

Existing Task

→ Previous Harness Handoff

→ Claude Code Local

→ New Native Claude Code Session

→ Same Workspace

→ Continue Task

## 21. 核心原则

请保持：

> **Harness identity stays native.**

> **Claude Code subscription is used through Claude Code itself.**

> **AgentFabric must not turn Claude.ai subscription into an API Provider.**

> **Harness sessions stay native.**

> **Same Harness means Resume.**

> **Different Harness means Handoff.**

> **Workspace + Handoff preserve task continuity.**

> **AgentFabric should be able to adopt work started outside AgentFabric.**

本阶段的核心目标不是简单“支持 Claude Code CLI”，而是：

> **让用户在 Claude Code 中工作到一半后，无论是额度耗尽还是主动切换，都可以通过 AgentFabric 把任务自然交接给另一个 Harness，并继续使用同一个 Workspace。**
